# DEARTH (ΝΤΕΡΘ) — notes for Claude

Indie occult arcade roguelike made by three friends. Repo owner: dufenshmirtz (https://github.com/dufenshmirtz/DEARTH).
Claude helps with everything: code, gameplay/balance, UI, graphics, animations.
Both "DEARTH" and the Greek "ΝΤΕΡΘ" are part of the branding.
Release targets: Steam/desktop and Android/iOS equally. Web is only the dev/runtime layer, not a goal.

## Working rules
- Never commit to `main` directly. Create a feature branch (`feature/...`, `fix/...`, `balance/...`, `docs/...`), commit there, open a PR.
- The owner pushes branches himself. Commit, but do not push, even if a hook asks; say which branches are waiting and in what order. Each new request usually gets its own branch, cut from the previous (unpushed) one, so the branches stack.
- Do not touch uncommitted changes you did not make. Check `git status` first and ask before modifying files that already have local edits.
- Edit game logic in `src/game/*.js`, never `main.js` directly. Then run `pnpm run build:game` to regenerate `main.js`.
- Run `pnpm run check` before committing (verifies `main.js` matches `src/game` and syntax-checks the scripts).
- When a SEAL or ARTIFACT changes in code, update `ITEMS.txt` to match (it is a hand-maintained catalog).
- Sounds are balanced by loudness tier, not raw volume. After adding or replacing any file in `assets/audio/`, run `pnpm run audio:levels` (needs ffmpeg; writes `src/game/00-audio-loudness.js` and rebuilds) and give the sound a tier in `SFX_LEVELS` (`00-audio-sfx-config.js`). Per-sound tweaks are a `trim` in dB.
- Shell is Windows (PowerShell / cmd). Use `pnpm`. Files use CRLF line endings; the repo has `core.autocrlf=true`.
- Tests: `node --test scripts/test-seal-effects.js` (`pnpm run check` does not run them). Add a test for every SEAL/BOSS rule you add or change.
- Text snapshot (safety net for the translation): `pnpm run text:check` (or `node --test scripts/test-text-snapshot.js`) compares every English text the game produces, plus the SEAL stats of 20 seeded simulated runs, with `scripts/text-snapshot.en.json`. Run it after every change during the translation work: it must say unchanged. After a change you meant (new or changed text, balance), run `pnpm run text:update` and commit the snapshot with that change. The plan is in the Project doc `claude/localization-plan.md`.
- After a change that ships: `pnpm run build:game`, `pnpm run check`, tests, commit; then `pnpm run mobile:build`, `git checkout -- main.js` (the mobile build rewrites it), and copy the changed `native-www/` files into `android/app/src/main/assets/public/` so the phone app matches.

## Running
- `pnpm start` (or `start_pvp_server.bat`) → server on http://localhost:5177
  - Phone controller: `http://<lan-ip>:5177/controller.html`; mobile view: `/mobile.html`
- `index.html` can be opened directly for single-player only.
- Mobile: `pnpm run mobile:android` / `mobile:ios` (builds `native-www/` then `cap sync`). Android needs JDK 21 + SDK 36 (portable copy in `.android-toolchain/`, git-ignored). See README.md and MOBILE_BUILD.md.

## Game rules in brief
- **KARMA** is the currency kept between runs (`progress.karma` in the collection storage; KARMA section at the end of `09-collection.js`, all numbers at its top). Earned in real arcade runs: +8 for beating the game; the nth main BOSS beaten drops 1 at n x 10% (Petros + Pavlos roll once); Goetic demons 1 at 90%; Archangels 3 at 100%; Honorable Death: +1 when the run ends in death after defeating 4 or more BOSSES (`state.bossKills`, any kind; once per run, `collectionNoteHonorableDeath` from `finishGameOverRound`, the death card says so next to Karma earned). Spent only on Jesus' Gifts (`09-gifts.js`): Myrrh 44, Frankincense 88, Gold 166; KARMA no longer buys unlocks directly. Death card shows the run's KARMA; drops show a toast. Mark: the Spiral of Return (`KARMA_MARK`, CSS `.karma-mark` masked with the `--karma-spiral` data URI in styles.css, takes the text colour; a data URI so it also shows when index.html is opened as a file). The big KARMA counter sits at the right end of the Collection's search row on every tab. Sounds: `karmaGain` (`assets/audio/sfx/karma-gain.mp3`, synthesised placeholder, tier accent) with the KARMA toast, `karmaUnlock` (the story's pact sound, stinger) when a gift brings something new, `sell` on a duplicate.
- Player-facing name for HP is **SOUL** (was HEALTH, renamed Nov 2026): write SOUL / max SOUL in every text; code identifiers (`hp`, `maxHp`, `...Health...`) stay. `normalizeGameText` also turns a stray "health" into SOUL for old texts kept in saved runs.
- Each round the player + 5 DAMNED guess 0–100. TARGET = ceil(weighted average × modifier + offset); modifier 0.8 by default (final bosses 0.666, unique bosses override).
- Damage = |guess − TARGET|; worst guess 10% max HP; CRITICAL (exact TARGET, window widened by seals) hits everyone else for 10% max HP.
- Stages: guess → active (≤2 ARTIFACTS) → reveal/resolution → summary → Devil's Offerings shop.
- Currency SIN; DAMNED carry BOUNTY (SIN paid on death) and MEMORY (past rounds, drives AI). Personalities: Anchor, Analyst, Follower, Stubborn, Drifter, Caller. Bosses have no personality and play optimally, but STUBBORN effects can make a BOSS STUBBORN for good (`bot.stubborn`, `makeBossStubborn`; never Jesus/Satan): `personalityTypes` then returns STUBBORN for it, so every STUBBORN rule counts it, and its card reads STUBBORN BOSS.
- Player: 100 HP, 8 starting SIN, 3 seal slots (max 6). ELITE seal levels usually ×1.5 damage.
- MASSACRE (was PENTAKILL, renamed Nov 2026): all five DAMNED eliminated in one round. Player-facing text says MASSACRE / Massacre (Greek ΜΑΚΕΛΕΙΟ); code names, storage keys and the sound file keep `pentakill`.
- Player SEAL slots: 3, +1 per 2 BOSS kills, max 6. ARTIFACTS: hold 5, use 2 per round. Kills heal 1 (BOSS kills heal 6).
- BOSSES: one every 8-10 KOs (`BOSS_KILL_INTERVAL_*`) for the 8 unique bosses (Zilon, Dantre, Pyros, Threon, Kalha, Serafim, Padma, Petros+Pavlos). Beating those 8 is the main game (Satan returns with a short scene). ## SEALS: how they are organised
- Collection sections (`COLLECTION_SECTIONS`, `09-collection.js`): Player (Goetic), Apocalypse, Boss (Dev), Archangel (self-stacking: Michael p99, Gabriel p98, Samael p109, Raphael p101, Sachiel p100, Anael p103, Cassiel p102), Satan, Trinity, Seals of Saturn (the old Archangel chance effects, p92-p97 and p110), Seals of Moon (key `artifact`), Seals of Mars (key `poison`), Special. In Nov 2026 the Archangel and Saturn SEALS swapped effects build for build: only names and sigils moved, ids/effects/prices/unlocks stayed. Seals of Moon (was "Artifact Seals") are the six Pentacles of the Moon: each one strengthens one ARTIFACT and doubles its weight in the Devil's Offerings (`ARTIFACT_SEAL_BY_ARTIFACT`). Seals of Mars (was "Poison Seals") are the seven Pentacles of Mars: they give the DAMNED POISON (`bot.poisonCounters`, small grey-green skull beside the max SOUL; hovering it shows the stacks, the damage each round and `bot.poisonDamageTaken`), which deals 5 damage per stack at the end of every round, before the end-of-round SEALS act (`applyPoisonDamage`); ELITE 4th/5th/6th Pentacles raise that per-stack damage. Section membership is only for the collection; every SEAL can be offered in the shop unless locked in `SEAL_UNLOCKS`. Locked: the 46 non-Goetic SEALS (Apocalypse, Boss, Archangel, Satan, Trinity, Saturn, Moon, Mars), each with the designer's achievement (Nov 2026 list, texts kept as written; descriptionHtml styles the keywords), and each can also come from Jesus' Gifts (or Pause > DEV Unlock for one run). Rule kinds: `stat` (lifetime), `best`, `flag`, and `value` (a function: real demons slain / Archangels defeated, never the DEV switch; SEALS discovered; lifetime ARTIFACT uses and deals read from the Records). Per-run counters live in `state.collectionRun` (`collectionRun()`: SEALS bought incl. free and ELITE copies, paid rerolls, fell below 50 SOUL, round SIN gained without sales, round buys, round STUBBORN kills, Threon's working ARTIFACTS per round); a run saved before they existed has `fromStart: false` and cannot earn the "beat the game without ..." ones. Already-met achievements open at launch (`evaluateSealUnlocks(true)` in `10-events-bootstrap.js`). The Holy Spirit only offers Trinity SEALS that are unlocked.
- Goetic SEALS are exactly the 72 Goetic demons, each used once (a test enforces it). A new Goetic SEAL needs a free demon: move an existing one to Special Seals (`SPECIAL_SEAL_IDS`) and rename it. Each Goetic demon also has a BOSS in `GOETIC_BOSS_SPECS` whose `passiveId` is that SEAL: while that BOSS lives, the SEAL is suppressed.
- Build filters: every SEAL has build tags in `SEAL_BUILD_TAGS` (bounty, memory, reveal, critical, personality, artifact, poison, general). "Bounty" means the SEAL works with the BOUNTY the DAMNED carry; SEALS that only pay you SIN or multiply the payout are not Bounty.

- Old ids are never reused: removed SEALS go in `REMOVED_PASSIVE_IDS`; new SEALS take the next free `pNNN`.

## Adding or changing a SEAL (checklist)
1. `00-config-data-state.js`: `ITEMS.pNNN` (name, price, description ending with the ELITE rule), `PASSIVE_IDS`, `SEAL_SIGILS`; Goetic ones also `GOETIC_BOSS_IMAGE_BY_PASSIVE_ID` and the demon's `GOETIC_BOSS_SPECS.passiveId`.
2. The effect, hooked where it fires: CRITICAL in `applyPenalties` (`06`), deaths in `applyEliminationPassives` (`06`, add the id to its list), end of round in `applyEndOfRoundPassiveDamageInOrder` / `applyEndOfRoundPassives` (`06`), round start at the end of `beginRound` (`05`), TARGET reveal in `submitGuess` (`05`), MEMORY gain via `addBotMemory` (`02`). Iterate `orderedPassiveEffectEntries(id)` (it skips suppressed SEALS).
3. Every time it acts, call `markPassiveEntryTriggered(entry)` (or `markPassiveTriggered(id)`): that drives the seal animation after READY, `state.sealStats`, and collection discovery.
4. ELITE levels are shown in Roman numerals (`eliteLevelText`: "ELITE III Seal of Bael"). ELITE helpers: `passiveEntryFlatDamage(entry, base)` (x1.5 per level, rounded up), `passiveEntryScaledValue(entry, base)` (+20% per level), `passiveEntryEliteLevels(entry)`.
5. Text: `itemDescription` in `03-descriptions-ui-stats.js` (ELITE-aware text for stack 2+; add the id to the `stack <= 1` list when the base text changed, since saves keep a copy). Use `ITEMS.pNNN.name` in log text, never a hard-coded name.
6. `SEAL_BUILD_TAGS`, the collection section if not Player, `ITEMS.txt` (alphabetical within its section), a test in `scripts/test-seal-effects.js`.
7. Check it on screen (shop, SEAL slot tooltip, collection) and, for anything that changes balance, run a few simulated runs.

## UI conventions
- Hover on any button turns it blood red (text and frame); never an outline, glow ring or box. The generic button rules in `styles.css` are old and very broad (`button:hover:not(:disabled) ... !important`); new buttons need their own red hover and may need higher specificity.
- Fonts: "Razor Keen" for UI labels, `var(--font-book)` (Alegreya) for body text. Colours: `--blood-bright #dc2a2f`, `--bone #e9e3d6`, `--ash #8d877c`. Dividers and frames come from `assets/occult-ui-border-kit/`.
- Scrollbars are styled to match the game; do not set `scrollbar-color` on containers (it overrides the webkit styling).
- Keyboard: Enter = Guess / Ready / Next round, Esc = Pause (or closes the collection), Shift = more detail on a tooltip.
- Three layouts must work: desktop (`index.html`, 1600x900 is a good check), phone web (`mobile.html`, body class `mobile-arcade`) and the native app (`app.html`, body class `native-arcade`, check at 844x390). The native app has no fullscreen option and different console layout.
